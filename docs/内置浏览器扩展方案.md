# 内置浏览器与扩展方案

正式交接版携带 Chrome++ 便携浏览器和 Maxwell 私有 OpenRPA MV3 扩展。扩展 ID 固定为：

```text
hpnihnhlcnfejboocnckgchjdofeaphe
```

## 发布包中的组件

```text
runtime/chrome-portable/                       内置 Chromium/Chrome++
runtime/maxwell-openrpa-extension/             Maxwell 私有扩展副本
runtime/OpenRPA.NativeMessagingHost.exe        Native Messaging Host
runtime/chromemanifest.template.json           注册表清单模板
runtime/browser-launcher/Maxwell.ChromeLauncher.exe
```

构建运行库时，`scripts/build-openrpa-runtime.ps1` 从固定基线的 Chrome 配置提取
MV3 1.0.0.6 扩展，保留 manifest key 以稳定扩展 ID，把 Native Messaging 名称
改为 `com.maxwell.openrpa.msg`，并加入 service worker 自动唤醒逻辑。

## 每个 Windows 用户的本机目录

运行时会在当前用户下准备：

```text
%LOCALAPPDATA%\Maxwell\BundledChrome
%LOCALAPPDATA%\Maxwell\BrowserProfile
%LOCALAPPDATA%\Maxwell\NativeMessagingHost
%LOCALAPPDATA%\Maxwell\OpenRpaExtension
```

- 当发布包位于 UNC/SMB 共享盘时，浏览器程序先原子复制到本机，避免 Chromium 子进程从网络路径启动失败。
- 浏览器配置首次从发布包的脱敏种子配置初始化；每位用户之后使用独立配置。
- Native Messaging Host 会复制到本机，并在 HKCU 下注册为 `com.maxwell.openrpa.msg`。
- 私有扩展会复制到本机；RuntimeHost 在执行浏览器流程前检查扩展和 Host 连接。
- Chrome++ 外层启动器会改写参数，因此 `Maxwell.ChromeLauncher` 负责定位并启动真实 Chromium 引擎，同时等待 UI Automation 文档树可用。
- 正式版启用 `--force-renderer-accessibility`，供 OpenRPA Windows 活动定位浏览器页面元素。

## 运行模式和编辑模式

- 运行模式：注册 Maxwell 私有 Native Messaging Host，允许 RuntimeHost 执行流程。
- 编辑模式：恢复本机正式 OpenRPA 的 Native Messaging manifest；没有安装 OpenRPA 时无法切回编辑模式。
- 切换模式后应完全退出 Chrome、OpenRPA 和残留 RuntimeHost，再重新打开。

## 发布安全要求

发布脚本会从浏览器种子配置删除登录数据库、历史记录、Cookie、会话、表单数据、网络状态和调试日志，只保留扩展安装与必要偏好。不得直接把开发机运行过的完整 `Data` 目录交给他人。

## 常见故障

- 提示 Host 正在使用：完全关闭 Chrome 后再试。
- 提示扩展缺失：重新解压完整正式包，不要只复制 EXE。
- 共享盘启动闪退：检查 `%LOCALAPPDATA%\Maxwell\BundledChrome` 是否可写、磁盘是否充足。
- 浏览器已开但元素定位失败：确认使用正式版内置浏览器，并检查 `--force-renderer-accessibility` 是否存在。
- 设计器无法录制：在设置中切换到编辑模式，并启动正式 OpenRPA 后重新打开 Chrome。
